# Quick Reference for Obsidian Assistant

## Vault-Specific Patterns

### Content Organization
- Check Resources.md for existing MOCs before creating new ones
- Most new content lands under Resources
- Always search first — MOCs probably already exist for common topics

### Common Migration Errors to Avoid
1. **Creating duplicate MOCs** — search for existing ones first
2. **Review vs Literature** — industry articles = review type, academic papers = literature type
3. **Missing both sides** — always update parent MOC when adding a child note

### File Naming Patterns
- Reviews: Keep original article title
- Guides: `Tool Name - Setup Guide.md`

### This Vault's Structure
```
Home
├── staging/Inbox.md (quick-capture scratchpad — regularly cleared)
├── staging/To Read Later.md (raw URL inbox — process with /obsidian-read)
├── Projects (active work)
├── Areas (ongoing responsibilities)
├── Resources (reference - where most new content goes)
│   └── [Your MOCs here — run /personalize to create seed MOCs]
└── Archives (inactive)
```

### Quick Checks Before Migration
1. Does a related MOC already exist? (search first!)
2. Is this staging/ content or archive/ content?
3. What type: atomic, review, literature, project, moc?
4. What related notes should be cross-linked?

### User Preferences
- Flat structure - everything in root, not nested folders
- Properties over folders for organization
- Always update parent MOCs when adding children
- Review notes need summary + key takeaways + reflection sections
- Don't rewrite content, just organize it

### Staging Directory Purpose
- Temporary holding for content to be organized
- Contains `Inbox.md` — quick-capture scratchpad (regularly cleared via `/obsidian-migrate`)
- Also contains clippings, drafts, or imports waiting to be processed
- Goal: Triage and move WIP files to proper locations via `/obsidian-migrate`
- **Never modify or promote staging files during vault audits** — use `/obsidian-migrate` instead

## Troubleshooting

### New files not appearing in Obsidian
Files created outside Obsidian (by Claude Code, git pull, scripts) often don't appear until reload. This is a **known Obsidian limitation** — the file watcher doesn't reliably detect external changes, especially in subdirectories. Quick switcher (Cmd+O) does NOT force a re-index.

**The only reliable fix:**
- **Cmd+P → "Reload app without saving"**
- **Pro tip:** Assign a hotkey in Settings → Hotkeys → filter "Reload" (e.g. Cmd+Shift+R)

This will happen regularly when Claude Code writes files or obsidian-git pulls changes.

## Migration Workflow Reminder
1. Check what's in staging
2. Identify type and relationships
3. Search for existing related content
4. Move (don't copy) files
5. Add proper frontmatter
6. Update parent MOCs
7. Verify staging is empty
